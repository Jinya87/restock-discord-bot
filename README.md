데스크패드는 제외합니다. 상품 자동 구매는 하지 않습니다.

## 실행 서버

GitHub는 코드 보관/검사용입니다. 정기 감시 설정은 없습니다.
별도 상시 서버에서 Dockerfile로 실행하세요. 컨테이너 비밀 환경변수 DISCORD_WEBHOOK_URL에 본인이 만든 웹훅 주소를 직접 입력합니다.
CHECK_INTERVAL_SECONDS=30이 기본입니다. 시작 시 연결 테스트 메시지를 보낸 뒤 감시합니다.
서버 계정 연결·결제·배포는 아직 진행하지 않았습니다.

## 판정과 한계

정상 조회 완료 후 30초 대기합니다. 로딩/전송 시간만큼 실제 간격이 늘어납니다.
조회 오류 시 5분 대기합니다. 실시간 감지와 결제 성공은 보장하지 않습니다.
컬리 키링 옵션에 가격이 있고 품절/disabled 표시가 없어야 구매 가능으로 판정합니다.
Hmall은 판매 중단이면 품절. 상품명이 시간의 오카리나+아크릴이고 활성 구매 버튼이 있어야 구매 가능입니다.
Hmall 재판매 시 옵션 구조는 아직 실판매 화면에서 검증하지 못했습니다.
페이지 오류·빈 화면·접근 제한은 재입고가 아닙니다. 사이트 제한은 우회하지 않습니다.
계속 구매 가능하면 중복 알림을 보내지 않고, 품절 후 재입고하면 다시 알립니다.
상태는 stock-state.json에 저장합니다. 컨테이너 재생성 시 상태가 초기화될 수 있습니다.
영구 디스크를 쓸 때 STATE_FILE=/data/stock-state.json 등으로 설정하세요. 부모 디렉터리가 존재해야 합니다.
알림 전송 후 상태 저장 실패 시 다음 실행에서 알림이 중복될 수 있습니다.

## 검사

python -m unittest -v : 옵션 판정/오류/중복 알림 방지 검사
python monitor.py --dry-run : 실제 두 상품 조회만, 알림 없음
python monitor.py --test-webhook : Discord 테스트 메시지 전송
GitHub Actions Bot Validation은 코드 검사와 수동 실사이트 조회 전용입니다.
GitHub에서 Discord 테스트를 하려면 Settings → Secrets and variables → Actions에 DISCORD_WEBHOOK_URL repository secret을 등록합니다.
서버 환경변수와 GitHub Secret은 서로 별개입니다. 웹훅을 코드나 채팅에 넣지 마세요.
